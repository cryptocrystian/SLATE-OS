# SLATE UX/UI Canon

## Design Objective

SLATE must feel like a premium internal operating system built by a high-end product studio.

It should visually extend the Saipien Labs website. A user should feel that the marketing site and product experience come from the same brand world.

SLATE should not look like a generic admin dashboard. It should feel like a crafted product: precise, useful, intelligent, refined, and trustworthy.

---

# Experience Principles

## Clarity First

Every screen should make the user’s next action obvious.

## Human-Guided AI

AI should assist, not dominate.

Rules:

- AI-generated findings must be labeled
- Important AI outputs require review
- Users can edit, approve, reject, or regenerate
- AI should not produce final client-facing output without approval
- Assumptions must be surfaced

## Product-Grade, Not Admin-Template

Avoid generic dashboard grids, bland tables everywhere, overcrowded forms, default-looking components, and cheap SaaS template aesthetics.

Use strong layouts, focused workspaces, polished cards, visual hierarchy, thoughtful empty states, and useful interaction details.

## Executive-Ready Outputs

Scorecards, findings, reports, roadmaps, and proposals must look like the beginning of premium deliverables.

## Progressive Disclosure

Use summary cards, detail drawers, expandable sections, tabs, step-based flows, filters, and status chips.

## Evidence Builds Trust

Insights should connect back to source material whenever possible.

# Color System

The product should share the website’s dark-mode palette.

## Base Surfaces

Use layered dark neutrals for page background, app shell, elevated cards, nested panels, borders, muted text, and primary text.

The background should not be flat black. Use subtle depth.

## Accent Philosophy

Use accents for primary actions, active nav states, score highlights, practice area identity, status emphasis, progress indicators, and selected matrix quadrants.

## Practice Accents

- AI Systems: cyan / electric blue / violet
- Custom Development: teal / green-blue
- Venture Studio: amber / magenta / warm violet

## Semantic Colors

Use tuned dark-mode semantic colors for success, warning, risk, critical, neutral, draft, approved, and needs review.

---

# Typography

Use a clean modern sans-serif for most UI/copy and a mono font sparingly for labels, scores, IDs, and metadata.

Suggested direction:

- Sans: Inter, Geist, Satoshi
- Mono: JetBrains Mono, Geist Mono, IBM Plex Mono

Avoid using mono for long text.

# Layout Canon

## App Shell

Recommended MVP layout:

- Left sidebar navigation
- Top utility/header bar
- Main workspace
- Optional right-side detail/context panel

### Left Sidebar

Should include SLATE mark/name, primary navigation, future practice switcher, and settings link.

### Top Bar

Should include page context, command/search trigger, review queue indicator, account/user menu.

### Right Context Panel

Use for selected lead summary, evidence, opportunity detail, AI assistant suggestions, and notes.

---

# Core UI Components

## Status Chips

Examples: New, Needs Review, High Fit, Approved, Draft, Final, Nurture, Converted.

## Score Cards

Used for AI Readiness, Workflow Friction, Systems Readiness, Internal Fit, Impact, Complexity.

## Finding Cards

Must show finding statement, category, evidence summary, confidence, sources, suggested business impact, review status, and actions.

## Opportunity Cards

Must show title, description, impact score, complexity score, risk score, priority label, related findings, and recommended next action.

## Evidence Blocks

Format: source type, source/person, excerpt/summary, confidence/weight.

## Report Section Cards

Must show title, status, summary, draft preview, linked findings, and edit/review action.

## Roadmap Cards

Show phase, objective, actions, dependencies, success criteria.

## Proposal Option Cards

Show option title, best-fit scenario, scope, timeline, deliverables, pricing placeholder, risks/assumptions.

# Key Screen Canon

## Overview Dashboard

Command-center view of new scorecards, high-fit leads, active audits, findings needing review, reports in progress, open proposals, and follow-ups.

## Lead Dashboard

Triage inbound leads and scorecard completions.

## Account Workspace

Company overview, contacts, stakeholders, scorecard results, engagements, documents, notes, recommended next action.

## Engagement Workspace

Stage tracker: Setup → Intake → Synthesis → Scoring → Report → Proposal.

## Findings Review Workspace

Three-column layout: findings list, selected finding/editor, evidence panel.

## Opportunity Matrix

Impact/complexity matrix with quick-win and strategic-build labels.

## Report Builder

Outline, section editor/preview, approved findings/evidence panel.

## Proposal Builder

Tiered options, scope builder, assumptions, implementation credit, terms.

---

# AI Interaction Canon

AI should be visible as an assistant layer, not a mascot.

Use subtle indicators: Generated, Confidence, Suggested by AI, Needs Human Review, Evidence Available.

Avoid chatbot mascots and overuse of sparkles.

Every important AI item should support approve, edit, reject, regenerate, and add note.

Confidence labels: High Confidence, Medium Confidence, Low Confidence, Needs Evidence.

---

# Motion Canon

Use subtle motion for transitions, panel reveals, hover elevation, score count-up, progress, node pulses, matrix placement, and approval feedback.

Avoid bouncy effects, heavy particles, heavy parallax, slow animations, or anything unserious.

---

# Empty State Canon

Empty states should guide action.

Example:

> No findings yet. Findings will appear after stakeholder intake responses or documents have been analyzed.

CTA: Send Intake Requests.

---

# Copy and Microcopy Rules

Voice: clear, human, practical, calm, credible, specific.

Avoid: “Unlock the power of AI,” “Revolutionize your business,” generic AI hype, excessive buzzwords.

Prefer: “Recommended next step,” “Needs review,” “Evidence available,” “Likely opportunity,” “Validate before implementation,” “Ready for consultant review.”

---

# Website Continuity Rules

SLATE and the website should share dark premium palette, typography, system node motif, interface card style, subtle technical grid, practice accent system, calm motion, and premium hierarchy.

The public scorecard flow should feel like moving from the website into a more application-like experience, not a separate form tool.

---

# Anti-Patterns

Do not build SLATE like a generic CRM, plain admin dashboard, project management clone, chatbot wrapper, form builder, spreadsheet with better colors, or cheap SaaS template.
